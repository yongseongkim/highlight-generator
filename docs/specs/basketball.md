# 농구 하이라이트 SPEC

상태: 종목 엔진·자동 코트 탐색의 설계. [공통 SPEC](README.md)의 관측·경계 계약을 따른다.
기본 참고 규칙은 [FIBA Official Basketball Rules 2026 v1.1](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2026-v1-1.pdf)이다
(2026-10-01 시행). NBA·NCAA·3x3·동호회 규칙은 별도 프로필이며 자동으로 혼용하지 않는다.

## 하이라이트와 필요한 증거

| 후보 장면 | 발견 신호 | 추가 확인 | 반례·미확인 항목 |
| --- | --- | --- | --- |
| 슛·3점·긴 거리 슛 | 슈팅 동작, 공의 림 접근, 코트 위치 | 슛 이전 전개, 공·림 주변 연속 관측, 결과 | 점프·팔 동작만으로 슛/성공 확정 불가 |
| 돌파·레이업·덩크 | 공격수의 이동, 수비와의 관계, 공·손·골대 | 공의 실제 움직임과 림 주변 상황 | 골대 근처 점프가 모두 덩크는 아님 |
| 블록·스틸·강한 수비 | 공 방향/제어 주체 변화, 수비 반응 | 접촉 주변 프레임, 상대 공격과 후속 전개 | 공과 손의 2D 겹침만으로 블록·파울 판단 불가 |
| 공격/수비 리바운드·팁인 | 실패한 슛 이후 공과 선수들의 움직임 | 공 제어·팀 관계, 후속 슛 | 공 근처에 있다는 이유만으로 소유권 변경 |
| 속공·좋은 패스 연계 | 팀 이동·볼 전진·연결된 공방 | 시작 지점과 공 제어, 마무리 | 선수들이 빠르게 달리기만 하는 장면 |
| 버저비터·클러치 | 경기 시계·점수 상황과 슛 | 실제 릴리스 시각과 시계의 동기, 결과 출처 | 시계 0:00 한 장이나 관중 반응만으로 성공 인정 |

득점만 하이라이트로 삼지 않는다. 실패한 슛을 막은 수비, 강한 돌파, 패스 전개도 관심도 후보가 될 수 있다.
자유투·일상적인 리바운드는 사용자 선호에 따라 낮은 우선순위로 두며, 자동으로 삭제하지 않는다.

## 코트·골대 탐색

FIBA 기준 코트는 길이 28m·폭 15m이고, 3점선 원호의 명목 반경은 6.75m다
([규칙 Article 2](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2026-v1-1.pdf)).
이 규격은 해당 ruleset의 템플릿이며 실제 촬영 구장이 규격을 따른다고 가정하지 않는다.

1. 직선·원호·페인트존·센터 서클의 후보와 골대/백보드 관측을 모은다. 배드민턴선과 분리해 여러 가설을 유지한다.
2. 사이드/엔드라인, 키 구역, 자유투선, 3점선의 연결 관계를 맞춘다.
   비스듬한 원은 영상에서 타원/원뿔곡선으로 보이므로 화면의 원 반지름만으로 규격을 판단하지 않는다.
3. 원본을 바닥 도면에 투영하거나 도면을 원본으로 투영해 사용하지 않은 선/원호에서도 일치하는지 검사한다.
   반 코트 화면에 가상의 전체 외곽을 이미지 모서리로 만들어 넣지 않는다.
4. 여러 골대가 있는 체육관에서는 보이는 모든 골대를 경기 대상으로 삼지 않는다.
   선택한 코트·공의 전개·활성 엔드를 결합하고 `court_id`, `basket_id`를 구분한다.
5. 바닥 homography와 림·백보드의 위치를 별도 관리한다. 공과 림을 바닥 평면에 내려 그린 결과로 골 여부를 판단하지 않는다.
6. 고정 카메라는 보정을 재사용하고, 이동/줌 카메라는 시점별 보정과 추적을 갱신한다.
   바닥이 거의 보이지 않는 림 확대 화면에서는 전역 코트 좌표를 미확인으로 남긴다.

[KaliCalib](https://github.com/DeepSportradar/2022-winners-camera-calibration-challenge)와
[DeepSportRadar calibration baseline](https://github.com/DeepSportradar/camera-calibration-challenge)은
농구 구장 탐색의 비교 후보다. 후자의 baseline은 선 분할·교차점·카메라 추정을 연결한다.
**교차점 부족 시 학습 구장의 평균 카메라로 대체하는 upstream 동작은 실제 보정 성공으로 수용하지 않는다.**
어댑터에서는 `uncalibrated`로 반환한다. 이 모델들은 현재 프로젝트에 연결되어 있지 않다.

## 공격 전개·슛·후속 상황

| 상태 | 다음 상태의 근거 | 공백 처리 |
| --- | --- | --- |
| `unknown` | 명시적 소유권 또는 일관된 제어 관측 | 가까운 선수에게 임의 배정하지 않음 |
| `controlled_attack` | 패스/돌파/슛 후보 | 가림 중에는 기존 팀 소유권을 확정 상태로 연장하지 않음 |
| `shot_candidate` | 림 근처 공의 진행·골 관련 이벤트 | 공이 사라지면 성공/실패 모두 미확인 |
| `rebound_contest` | 같은 팀의 재공격, 다른 팀의 제어, 경기 중단 | 공격 리바운드는 같은 공격 전개의 연속일 수 있음 |
| `terminal_candidate` | 득점/중단/명시적 소유권 변경 | 점수 OCR 지연은 정확한 종료 시각이 아님 |

공격이 시작된 근거가 있으면 그 시작부터 후속 결과까지 보존한다. 없으면 기존 득점 이벤트 기반 경로의
기본 앞 8초 맥락이나 bounded 움직임 문맥을 사용하되 **전체 possession이라고 표기하지 않는다**.
슛 직후 공을 놓쳤다고 리바운드·블록·스틸을 만들어내지 않는다.

FIBA의 골 정의는 살아 있는 공이 위에서 바스켓 안으로 들어가 머물거나 완전히 통과하는 조건을 포함한다
([Article 16](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2026-v1-1.pdf)).
영상 엔진은 `shot_attempt_candidate`, `rim_crossing_candidate`, `made_inferred`, `miss_inferred`, `unknown`을 구분한다.
기존 `shots.py`의 상대 위치 규칙은 `made_inferred` 수준의 증거이며, 공식 득점 이벤트나 사람이 확인한 결과와 구분한다.

2점/3점은 슈터가 슛할 때 적용되는 규칙을 따라야 한다. 바닥 위치가 보이지 않거나 점프·릴리스 시각이 불명확하면
득점 가치를 미확인으로 둔다. OCR로 보인 점수 변화는 안정된 여러 관측과 팀 매핑으로 확인하고,
가려짐·리플레이·수정·다른 경기 점수판을 반례로 남긴다. 골텐딩·파울·트래블링의 자동 심판은 이번 범위가 아니다.

## 모델과 실행 계획

| 역할 | 우선 후보 | 사용 범위 |
| --- | --- | --- |
| 선수·공 발견 | 기존 YOLO; 데이터가 있으면 농구공/림 전용 검출기 | 포즈와 별개인 공 관측 경로; 일반 `sports ball`의 종목은 문맥으로 확인 |
| 드문/불명확한 객체 | SAM3 / YOLOE | 전역 독립 탐색과 후보 crop, 고정 예비 공 반례 기록 |
| 선수 ID 연결 | ByteTrack; 이동 카메라에서 BoT-SORT 비교 | 검출 박스 연결; 팀·실제 선수 신원과 분리 |
| 특정 공/선수의 짧은 추적 | SAM2.1 / SAMURAI | 초기 대상을 확인한 뒤 선택 구간만 사용, 실패 시 재탐색 |
| 코트 | OpenCV 규격 일치 + KaliCalib/DeepSportRadar 비교 | 선/교차점 가시성이 충분한 시점에서만 보정 |
| 점수·시계 보조 | PaddleOCR 등 작은 OCR | 명시한 점수판 crop을 낮은 주기로 읽고 여러 프레임에서 검증 |

초기 실험은 포즈 5–10FPS 수준과 별도의 공 검출을 비교하고, 림 주변 사건은 원본의 연속 30/60FPS 구간으로 확인한다.
이는 **튜닝 출발점**이며 이 속도를 달성했다는 측정값이 아니다. SAM을 림 주변 모든 프레임의 기본 모델로 고정하지 않는다.
공이 림에 접근하지 않은 돌파/수비도 독립 경로로 남긴다.

[DeepSportRadar ball 3D](https://github.com/DeepSportradar/ball-3d-localization-challenge)는
알려진 공 중심과 공 크기 추정·카메라 보정을 이용하는 과제다. 범용 공 발견기를 이미 제공한다고 해석하지 않는다.
모델·가중치·Mac 상태는 [조사 보고서](../research/vision-models-2026-11-19.md)를 따른다.

## 수용 기준

- 바닥의 배드민턴선·반사·체육관의 비활성 골대를 선택하지 않아야 한다.
- 3점선/페인트존 일부만 보이는 화면과 림 확대 화면의 공간 신뢰도를 구분해야 한다.
- 슛 실패·블록·공격 리바운드·수비 리바운드·연속 팁인을 서로 다른 관측 시나리오로 검사한다.
- 정지 예비 공과 공의 미검출이 득점/소유권 변화로 승격되지 않아야 한다.
- 슛 전에 포즈가 없어도 공·CV·독립 SAM에서 검토 후보를 만들 수 있어야 한다.
- 평가에서 슛 시점·성공 여부·팀/소유권·2/3점 가치·전개의 완결성·관심도·Mac 비용을 별도로 보고한다.
